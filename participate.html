Help shape the community

SIDM is intended to be useful to people who develop, implement, govern or rely on health and care information standards. You can contribute expertise, questions, evidence or practical experience.

Ways to participate

  1. Explore the current ideas

    Read the proposed areas of work and the public GitHub issue list before creating a new topic.

  2. Raise a question or suggest a project

    Open a GitHub issue explaining the problem, the people affected, the outcome sought and any useful references. A short starting point is sufficient. A repository maintainer can add the project label to an appropriate proposal so it appears on the website automatically.

  3. Contribute to a proposal

    Comment on an existing issue, share evidence or offer to help. Practical counterexamples and respectful challenge are as welcome as supporting arguments.

  4. Suggest improvements to the website

    The source is in a separate public website repository. You can suggest a change through an issue or contribute a pull request.

Participation expectations

Focus on the topic rather than the individual. Explain the basis for technical claims, distinguish evidence from proposals, respect intellectual property and do not publish confidential information, patient data or personal information about other people.

Material submitted to a public repository is public. You need a GitHub account to create or comment on an issue, but not to read the website or public discussions.

Membership and formal roles

Reading the website and making a public contribution do not require BCS membership. Formal SIDM membership, any standing working groups and decision rights require separate community governance arrangements, which should not be inferred from participation on GitHub.

Why GitHub?

GitHub provides an accessible public record of issues, contributions and document changes without requiring SIDM to build a database or manage its own mailing list. Its limitations should also be recognised: GitHub sign-in may be a barrier for some participants, and it is not a private discussion platform.

For now we use GitHub Issues. A dedicated GitHub Discussions forum may be enabled later if the community agrees it would be useful.
